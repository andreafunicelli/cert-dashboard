Binding match states

A binding is one certificate/key pair that a virtual host is configured to use on a server. Discovery compares what is on disk with the certificate inventory and records a match state. The dashboard only reports these states: it does not fix them, because correcting a server's files is your decision.

These are stored observations, not desired-deployment or live TLS verdicts. A matched certificate need not be the certificate you intend to deploy. Stale means the latest discovery did not succeed, not that this certificate changed.

matched
The certificate file on disk is a certificate in the inventory and the key at the configured path belongs to it.
unknown
The certificate file on disk is not in the inventory. Import it to track it.

Drift: key_mismatch

The private key at the configured path does not belong to the certificate at the configured path. The web server would fail to start or reload with this pair.

The dashboard does not fix this. Check the virtual host's ssl_certificate_key (nginx) or SSLCertificateKeyFile (Apache) setting and the files on the server, put the right key in place, then run discovery again.

While a binding is in this state, the dashboard blocks deploys of that virtual host so a new certificate is never written next to a key that does not match.

File failure: missing_file

The certificate file named in the configuration is missing or could not be read when the server was last discovered.

The dashboard does not fix this. Check the path in the configuration and the file's owner and mode on the server, restore the file or correct the path, then run discovery again.
