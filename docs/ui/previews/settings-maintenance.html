Master key rotation

Rotation is a command-line operation; this page never edits the keyring or rotates keys. Current state:

  • Active version 1; loaded versions: 1
  • Rows not yet on the active version: 0
  • Versions referenced by stored keys but missing from the keyring: none

Run these on the dashboard host as root (full procedure: docs/operations.md, section 6). Take a database backup first.

  1. Generate the next version into a new file in a temporary 0700 directory owned by the container user, merging the current keyring (live limit: two versions). The current master_key is mounted read-only at /secrets and the new file is written to /out; both paths exist only inside this one docker run: 
    set -eu
tmp="$(mktemp -d /tmp/cert-dashboard-keyring.XXXXXXXX)"
install -d -m 0700 -o 10001 -g 10001 "$tmp"
docker run --rm -v /etc/cert-dashboard/secrets:/secrets:ro -v "$tmp":/out cert-dashboard:local \
  python -m app.cli generate-master-key --version 2 --merge /secrets/master_key --output /out/master_key.v2.new
sha256sum "$tmp/master_key.v2.new"
    The command prints only sha256=<digest> path=<file>; the digest must equal the sha256sum output.
  2. Keep a copy of the old file in the backup location, install the verified file as the master_key secret and restart so new writes use it: 
    install -m 0400 -o 10001 -g 10001 "$tmp/master_key.v2.new" /etc/cert-dashboard/secrets/master_key
shred -u -- "$tmp/master_key.v2.new" && rmdir -- "$tmp"
docker compose up -d --force-recreate web worker
  3. Re-encrypt every key and TOTP seed (batched, idempotent, resumable): 
    docker compose run --rm web python -m app.cli rotate-master-key
  4. Verify a keyed certificate (metadata only is printed): 
    docker compose run --rm web python -m app.cli verify-key --certificate-id ID

Secret files are read once at startup: replace the file, rerun scripts/install-secrets.sh and restart the service.
